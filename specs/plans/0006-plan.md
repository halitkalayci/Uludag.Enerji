## Files to change or add
- `scripts/worktree` (yeni) — tek komut, dört alt komut:
  - `new <branch>`: `git fetch --prune`; branch'in worktree'si varsa yolunu yazar (sürdürme); branch
    varsa ama worktree'si yoksa onu bağlar; yoksa `origin/main`'den branch + worktree açar. Dizin:
    `<ana ağacın üst dizini>/<repo adı>-<branch, "/" → "-">` (K-3), yalnız **mutlak yol**.
    `--unset-upstream`. Sonraki adımı yazar (`npm ci --prefix ECommerce/client`).
  - `merged <branch>`: K-2 kanıtı; exit 0 = merge'lü, 1 = değil. Her kontrol satır satır `ok`/`FAIL`.
    Squash yolu: `gh pr view <branch> --json state,headRefOid,mergeCommit --jq …`.
  - `clean <branch>`: `merged` + CB-6 temizlik ön kontrolü (değişiklik, izlenmeyen dosya, push
    edilmemiş commit) → `git worktree remove` → `git worktree prune` → `git branch -D` (squash'ta
    `-d` reddeder; kanıt alındıktan sonra güvenli) → `git push origin --delete` (yoksa hata değil) →
    `git fetch --prune`. Sonunda dört kalıntının durumu: `absent`/`REMAINS <ad>`; kalan varsa exit 1.
  - `sweep`: ana ağaç dışındaki her worktree için `clean`; merge'lü olmayan ya da kirli olan yalnız
    raporlanır. Çağıran oturumun kendi worktree'si silinmez, yalnız raporlanır.
- `scripts/worktree-test` (yeni) — kabuk test paketi (`scripts/selftest` stili): repo dışında geçici
  dizinde bare `origin` + klon + worktree'ler kurar; squash PR'ı `PATH` önüne konan sahte `gh` ile
  taklit eder; hook'lara JSON besler. Gerçek repoya ve ağa dokunmaz.
- `scripts/check.conf` — yeni adım `worktree [fast]: sh scripts/worktree-test`; `requires worktree: git --version`.
- `.claude/hooks/worktree-guard.sh` (yeni) — PreToolUse (CB-2):
  - Edit/Write/MultiEdit/NotebookEdit: `file_path` ana ağacın altındaysa exit 2.
  - Bash: komutun çalıştığı dizin (`cd <yol> &&` / `git -C <yol>`, yoksa `cwd`) ana ağaçsa ve komut
    `checkout|switch|commit|merge|pull|stash|reset|restore|add` git alt komutu içeriyorsa exit 2.
  - Ana ağaç = `git rev-parse --path-format=absolute --git-common-dir`'in üst dizini; Windows yolları
    `cygpath -m` (varsa) ile normalize, büyük/küçük harf duyarsız karşılaştırma.
- `.claude/hooks/worktree-sweep.sh` (yeni) — SessionStart: `scripts/worktree sweep` çıktısını oturuma
  bağlam olarak verir (K-4); hata oturumu durdurmaz.
- `.claude/settings.json` — iki hook kaydı (mevcut `protect-shipped` aynen kalır).
- `docs/git.md` — yeni `## Worktrees` bölümü (kural, K-1…K-6, komutlar, merge kanıtı, temizlik, sınırlar).
- `AGENTS.md` — Operating mode altına bir satır + "Where things live" tablosuna bir satır.

## Risks & open questions
- **R-1 Ortam (doctor):** fast ve full profil bu worktree'de koşamıyor — tek eksik
  `ECommerce/client/node_modules`. *Öneri:* adım 0'da `npm ci`; diğer önkoşullar (dotnet 9, node ≥20,
  docker) karşılanmış.
- **R-2 Göreli yol tuzağı (yaşandı):** `git -C <ana ağaç> worktree move <göreli>` hedefi ana ağacın
  içinde açtı. *Öneri:* script yalnız mutlak yol üretir; test senaryosu dizinin ana ağacın kardeşi
  olduğunu doğrular.
- **R-3 Sweep'in otomatik silmesi:** SessionStart her oturumda `gh` çağırır (worktree başına ~1 sn) ve
  doğrulanmış + temiz worktree'leri siler. *Öneri:* onaylanan K-4 böyle; çağıranın kendi worktree'si
  hariç; `gh` yoksa/yetkisizse squash yolu `FAIL` olur ve hiçbir şey silinmez (güvenli taraf).
- **R-4 Bash tespiti sezgisel:** `cd`/`-C` ayrıştırması her kabuk biçimini yakalamaz (S-1 sınırı).
  *Öneri:* yanlış pozitif (worktree'deki komutu engellemek) testlerle sıfırlanır; kaçak (yakalanmayan
  yazma) belgelenir. Ana ağaçta tehlikeli olan asıl işlem branch değiştirmek — o yakalanır.
- **R-5 Hook'un devreye girmesi:** ana ağaç bu değişikliği içeren branch'e geçene kadar hook yok
  (spec, Out of scope). *Öneri:* kabul; geçişte kural belgeler + bellekle uygulanır.
- **R-6 `adapters/` dokunulmaz:** bunlar ANEW şablon kaynakları (`/upgrade` yönetir); projenin canlı
  ayarı kökteki `.claude/`. *Öneri:* değiştirmiyoruz; doctor'ın adapter parity kontrolü komutlara
  bakar, yeni komut eklemiyoruz.
- **R-7 CI:** `worktree` adımı ubuntu'da `sh` + `git` ile koşar; test repolarında commit kimliği
  `-c user.name/-c user.email` ile verilir (CI'da global kimlik yok). Ağ ve `gh` gerektirmez (stub).
